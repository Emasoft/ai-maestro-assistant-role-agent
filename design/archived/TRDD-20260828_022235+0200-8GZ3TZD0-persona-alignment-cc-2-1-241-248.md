# persona alignment with Claude Code 2.1.241 to 2.1.248

Successor to TRDD-HSJ1D0A6, which did the same job for 2.1.233–2.1.240. Filed at
`column: complete` after the work shipped in one session, and archived in the same
commit — it is a record, and says so.

## Method

The 2.1.241–2.1.248 changelog was distilled to the 15 bullets that could bind a
persona-only role-plugin, then four read-only lean-worker scans ran in parallel over
disjoint surfaces (persona · tests · docs · config). Every finding they returned was
re-verified first-hand before any edit; the deciding code is quoted below rather than
taken on an agent's word.

## What changed (3 persona facts, each newly pinned)

- **A subagent's `SendMessage` is the PARENT's send** (2.1.248). The reply lands in
  this session's conversation, not the subagent's. The persona already invited
  subagent fan-out AND described this channel, but never joined the two, leaving the
  reply unowned — and an unowned peer message is exactly the inbound *Self-defense*
  says to distrust.
- **A subagent stopped at `maxTurns` now returns PARTIAL output** (2.1.246), resumable
  via `SendMessage`, instead of appearing finished. The persona said "treat what one
  reports back as findings to verify"; verifying a half-finished scan as a whole one is
  the false conclusion that instruction exists to prevent.
- **`ListAgents` reports the caller's OWN addressable name** (2.1.239). R39.7 makes
  this agent invisible to other AGENTS, not to other sessions, so its handle being
  enumerable is not an invitation.

Pins: two rows added to `_CURRENT_REACH` in `tests/test_transport_claims.py` (the
channel facts) and one new test in `tests/test_agent_definition.py` (the partial-result
fact). All three were **proven to bite** by running the new patterns against the
pre-edit persona from `HEAD` — each failed there and passes now.

## What was deliberately NOT done

- **`experimental.cacheTtl` in the agent frontmatter was declined.** Verified: CPV
  5.11.0 carries `experimental` in neither `PLUGIN_SHIPPED_AGENT_ALLOWED_FIELDS` (the
  15 plugin-shipped fields) nor `KNOWN_FRONTMATTER_FIELDS`, so
  `validate_agent.py:243-247` would emit an unknown-field WARNING on every validate.
  The publish gate tolerates it (`scripts/publish.py:944-947` blocks only on exit
  `1..4`; WARNING is `5+`), so this is noise rather than a block — but the field is
  `experimental.*`, it governs the per-agent TTL used *when no subagent TTL setting is
  configured*, and this repo ships a MAIN agent whose caching is governed by the user's
  own `promptCacheTtl`. It buys a permanent warning against a pinned v5.5.0 validator
  and delivers nothing to a consumer of this plugin. Revisit when CPV knows the field.
- **No config, README, or PRRD change.** The docs scan returned zero findings; the
  README transport mirror is in sync and the corpus-wide guard in
  `test_transport_claims.py` covers it. The repo ships no settings file, so
  `promptCacheTtl` / `subagentPromptCacheTtl` / `modelPicker` are user-machine concerns
  outside it, and it ships no skills directory, so the `skills/*/SKILL.md` reload fix is
  inert here.
- The remaining 11 distilled facts (`--restricted`, cross-session on
  Bedrock/Vertex/Foundry, `crossSessionInbound` warn-vs-refuse, the /tmp fallback,
  `SendFeedback`, the `workflow-authoring` split, subagent model-404 fallback, `/loop`,
  `/code-review`, the 30s socket rule) touch no claim this plugin makes. No finding was
  invented for them.

## Post-commit review pass

An adversarial review of the commit found four claims measured by PROXY rather than
directly. Each was then settled against the thing itself, and two changed the record:

- **Test baseline.** "was 112" was quoted from HSJ1D0A6, never run. Measured at `HEAD~1`
  in a scratch checkout:
  **113**. The arithmetic (113 + 1 new test = 114) holds; the cited baseline did not.
- **cspell.** The first check filtered output through a hand-written list of
  assumed-pre-existing words — a substring filter that could mask a genuinely new
  unknown. Redone as a real before/after set difference over the three changed files:
  7 unknowns before, 7 after, **empty in both directions**. A second pass established
  that this repo's `words:` list is irrelevant to these three files (running them
  against the real config and against an empty one yields the identical 7), so the
  difference never depended on which config was loaded — the measurement holds either
  way.
- **mypy.** The project gate (`mypy scripts/`) never type-checks `tests/`, where two of
  three edits live, so the green gate proved nothing about them. Run explicitly against
  both edited test files: clean.
- **CPV version.** The first read was of cached 5.11.0; `publish.py` pins **v5.5.0**.
  Re-read at the pinned tag: identical `report.warning` path, `experimental` absent from
  `KNOWN_FRONTMATTER_FIELDS`. The decline stands on the version that actually gates.

One weakness is acknowledged and NOT fixed: these regexes pin a PHRASE, not a claim, so
an honest reword can delete a guarantee while the suite stays green. The pattern is the
existing `_CURRENT_REACH` design, but this card **extended** it — two new rows and one
new test in the same style — so the honest statement is "extended the weak pattern and
hardened one of the three", not "inherited it". Replacing phrase-pinning with something
that survives rewording is its own card, not this one.

The review also judged the partial-result pin too weak — `marked partial` is two
ordinary words a reword could keep while inverting the sense. It now pins the recovery
clause (`resumable with \`SendMessage\``) as a second assertion, so the fact cannot be
half-deleted. Proven to bite against the pre-edit persona.
